# TT_AUTOMATIZATION: контекст для Claude

Система автопубликации видео в TikTok на n8n (локально: Docker Desktop + ngrok) с панелью управления на GitHub Pages. Масштаб: 50–1000 аккаунтов. Язык общения с владельцем: русский. Тексты панели и страниц сайта: английский.

Если ты начинаешь с нуля (новый владелец, ни ключей, ни данных): сначала прочитай `docs/ONBOARDING_FROM_SCRATCH.md` (что должен сделать человек сам: аккаунты, доступы, порядок установки) и `docs/DATA_MODEL.md` (таблица, папки, форматы файлов). Обзор проекта: `docs/HANDOVER.md`.

## Карта репозитория
- `workflows/` готовые воркфлоу n8n (01, 03–08), **привязка к Data table по имени** `tiktok_accounts`. Это набор для импорта на новой установке.
- `infra/files/workflows/` те же воркфлоу, но привязка по ID таблицы прежнего владельца. На новой установке НЕ использовать; генераторы пишут в оба места.
- `tools/` генераторы воркфлоу: `gen01.py` (подключение аккаунтов), `gen03.py` (API кнопки Publish), `gen04.py` (ручная публикация), `gen05.py` (API панели), `gen06.py` (06 планировщик + 07 подготовка + 08 публикация), `blocks.py`/`snippets.py` (общий JS-код узлов), `templates/` (исходные шаблоны узлов). Воркфлоу править ТОЛЬКО через генераторы.
- `scripts/` и `infra/files/scripts/` (копии, должны совпадать): `make_variants.sh` (видео + хук), `add_music.sh`, `analyze_mood.sh`, `extract_frames.sh`, `backup_local.ps1`.
- `infra/` Docker: `docker-compose.local.yml`, `Dockerfile` (n8n + ffmpeg), `Caddyfile.gate` (шлюз), `.env.example`.
- `site/` панель (`console.html`, один файл с JS) и страницы `privacy/terms/index` для TikTok. Публикуется отдельным репозиторием через GitHub Pages.
- `docs/` документация, `legacy/` устаревшее (Google Sheets), не использовать.

## Как менять воркфлоу (обязательный порядок)
1. Правка в `tools/genNN.py` или `tools/blocks.py`, затем `python tools/gen0N.py` (все генераторы запускаются из корня репозитория).
2. Проверка синтаксиса кода каждого Code-узла: выгрузить `parameters.jsCode`, обернуть в `(async function(){ ... })`, `node --check`. Проверить, что все связи (`connections`) ссылаются на существующие узлы.
3. Деплой: `docker exec <n8n> n8n import:workflow --input=/files/workflows/<файл>.json`, затем `n8n publish:workflow --id=<id>` для каждого активного воркфлоу, затем `docker restart <n8n>`. Execute Workflow вызывает только АКТИВНЫЕ воркфлоу.
4. Тест на живой системе в `DRY_RUN=1` (в TikTok ничего не уходит), потом вернуть `DRY_RUN=0`.
Ошибки Code-узла видно только в журнале выполнений n8n; в Code-узлах доступны модули `fs, https, http, path, crypto` (задано в `NODE_FUNCTION_ALLOW_BUILTIN`), глобального `URL` нет.

## Критичные правила и ловушки
- **Секреты:** `.env`, токены, ключи, `accounts.json`, `invites/`, `identity/`, базу n8n никогда не коммитить и не вставлять в чат (`.gitignore` это закрывает). Токены TikTok в таблице хранятся зашифрованными (`enc:` + AES-256-GCM, ключ из `N8N_ENCRYPTION_KEY`). Потеря этого ключа = все аккаунты надо подключать заново.
- **Авторизация панели:** ключ `CONNECT_SECRET` только в заголовке `Authorization: Bearer`. Никогда не передавать ключ в URL/теле. Подключение аккаунта из панели идёт через одноразовый билет (`connectTicket` → `tiktok-start?ticket=`). Rate-limit: 10 ошибок за 10 минут блокируют IP на 15 минут (`state/auth_fail/`).
- **Наружу только `/webhook/*`:** ngrok указывает на шлюз Caddy (`gate:8080`), редактор n8n доступен лишь на `http://localhost:5678`. Не открывать порт n8n в интернет.
- **Имена аккаунтов:** только `[a-z0-9_-]{1,40}`, всегда в нижнем регистре (Windows не различает регистр папок), не зарезервированные имена Windows (con, prn, aux, nul, com1-9, lpt1-9).
- **Файлы состояния:** `accounts.json` и `schedule.json` пишутся атомарно с `.bak`; при повреждении восстанавливаются из `.bak`, если копии нет, запись запрещена (не затирать!). Не править их вручную при работающем n8n.
- **Защита от дублей:** метки `state/published/<хэш>.json` (видео ставится в «опубликовано» сразу после init в TikTok), блокировка аккаунта `state/locks/acct_<имя>` (20 минут), один глобальный лок для ручного запуска.
- **Code-узлы с долгими операциями:** Execute Command обёрнуты в `timeout`. Не ставить `saveDataSuccessExecution: none` (виснут выполнения).
- **Git Bash на Windows:** для `docker exec` с путями задавай `export MSYS_NO_PATHCONV=1`; многострочный Python с обратными слэшами пиши в файл, а не в heredoc; PowerShell 5.1 читает скрипты без BOM как ANSI (для `.ps1` с кириллицей нужен UTF-8 BOM).
- **Тесты:** тестовые аккаунты называть `zz*`, после тестов удалять их, их слоты, записи в `posts.jsonl` и вернуть `DRY_RUN=0`.
- **Правила TikTok:** не делать автоматическую регистрацию аккаунтов, генераторы почт, обход региональных блокировок, антидетект. Аккаунты подключают владельцы сами через официальный вход (TikTok Login Kit) или по ссылке-приглашению. Метка `is_aigc` ставится для AI-видео. Запрашивать только scopes `user.info.basic`, `video.publish` (статистика `video.list` скрыта флагом `STATS_ENABLED=0`).

## Состояние проекта
- Реализовано и проверено: подключение аккаунтов (панель и приглашения), публикация из папок (кнопка), планировщик со слотами (06/07/08), панель (Overview, Videos, Texts, Accounts, Schedule, Invitations), пулы хуков/подписей/хэштегов, музыка по настроению, бэкап.
- НЕ сделано: аудит приложения TikTok (до него все посты приватные, `TIKTOK_PRIVACY=SELF_ONLY`, аккаунт должен быть закрытым). Нужно записать демо-видео, отправить заявку, после отправки сменить `CONNECT_SECRET`.
- НЕ проверено на реальном TikTok: подключение по приглашению и публикация через планировщик (проверялось в `DRY_RUN`).
- Открытые доработки: подтверждение при несохранённых правках в панели, статус `Check` в журнале отдельно от `Published`, пересоздание будущих слотов при смене профиля, показ `ai_error` на вкладке Videos, версия `schedule.json`, `deleteInvite`.
- Все изменения панели (`site/console.html`) тестировались в jsdom против живого API; проверяй панель так же (через `jsdom` и вызовы `fetch` на настоящий сервер).

## Принципы работы с владельцем
- Не выполнять необратимых или внешних действий (push, удаление данных, смена секретов) без явного разрешения.
- Объяснять простыми словами, без жаргона; сообщать честно, что проверено, а что нет.
