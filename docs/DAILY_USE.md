# Ежедневная работа: публикация из папки

Условия: включён ПК, запущен Docker Desktop (n8n и ngrok стартуют сами). TikTok-аккаунт подключён в консоли.
Консоль: https://lexus0333.github.io/legal/console.html (адрес сервера и ключ доступа `CONNECT_SECRET` из `infra/.env`).

## Как публиковать
1. Положите видео (mp4, mov, m4v) в папку `infra/files/inbox/<имя аккаунта>/`, например `inbox/account1/`.
2. По желанию рядом положите текстовый файл с тем же именем (`ролик1.mp4` и `ролик1.txt`): первая строка = хук (текст на видео в первые секунды), остальное = подпись. Хэштеги пишите прямо в подпись.
   Если файла нет, подпись берётся из имени видео, а хука не будет.
3. Откройте консоль и нажмите **Publish all videos**. Видео публикуются по очереди, между постами пауза 5-15 минут (настраивается в `.env`: `POST_PAUSE_MIN_SEC`, `POST_PAUSE_MAX_SEC`).

## Куда уходят файлы
- Пока видео не опубликовано, его папка остаётся в `inbox` нетронутой (в работу берётся копия).
- После публикации папка ролика переезжает целиком, со всем содержимым, в `infra/files/done/<аккаунт>/<папка ролика>/`. Рядом появляются `<имя>_published.mp4` (готовое видео, которое ушло в TikTok, с хуком) и `<имя>_post.json` (хук, подпись, хэштеги, ID публикации). Если в папке несколько видео, переезжает только опубликованное, остальные остаются в очереди.
- С ошибкой: так же в `infra/files/failed/<аккаунт>/` плюс `<имя>_error.txt` с причиной. Причина видна в консоли и приходит в Telegram.
- Если проблема с аккаунтом или приложением (не подключён, нужен закрытый профиль и т.п.), ничего не переносится, очередь останавливается.
- Журнал: `infra/files/posts.jsonl`.

## Хуки, подписи, хэштеги по умолчанию
Если у ролика нет своего `.txt` и ИИ не настроен, берутся случайные из пулов `infra/files/pools/<язык>/hooks.txt`, `captions.txt`, `hashtags.txt` (одна строка = один вариант; язык задаёт `POOL_LANG=en|ru` в `.env`). Пулы можно редактировать. Пустой `hooks.txt` означает видео без текста в кадре.

## Сколько видео за одно нажатие
`MAX_POSTS_PER_RUN` в `.env` (по умолчанию 5). Между постами пауза `POST_PAUSE_MIN_SEC`-`POST_PAUSE_MAX_SEC`.

## Хук и подпись от ИИ (необязательно)
Задайте в `infra/.env` `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL` (любой сервис с OpenAI-совместимым API, доступный из вашего региона). Если ИИ недоступен, публикация не останавливается: текст берётся из `.txt` или имени файла.

## Тестовый прогон без публикации
`DRY_RUN=1` в `infra/.env`, затем `docker compose -f docker-compose.local.yml --env-file .env up -d n8n`. Всё делается, но в TikTok ничего не отправляется, а видео возвращается в `inbox`. После теста верните `DRY_RUN=0`.

## Пока приложение TikTok не прошло аудит
Все посты приватные (видны только владельцу), а сам TikTok-аккаунт должен быть закрытым (Настройки -> Конфиденциальность -> Закрытый аккаунт). После одобрения аудита смените `TIKTOK_PRIVACY=PUBLIC_TO_EVERYONE`.

## Панель на сайте (вкладки)
- **Overview:** по каждому аккаунту запас видео, сколько опубликовано (всего и за 7 дней), ошибки, время последней публикации, шаги онбординга (добавлен, подключён, есть видео, первая публикация, активен), предупреждения (не подключён, мало видео, скоро истекает вход в TikTok) и очередь.
- **Videos:** все публикации с фильтрами по аккаунту и статусу: дата, видео, хук, подпись, результат. Колонки просмотров, лайков, комментариев и репостов скрыты, пока не включена статистика (`STATS_ENABLED=1`; для неё понадобится право `video.list` после одобрения приложения TikTok, и только по публичным постам).
- **Texts:** списки хуков, подписей и хэштегов: общие и отдельные для каждого аккаунта (кнопки Save и Use default list). Старая версия списка сохраняется рядом как `.bak`.
- **Accounts:** добавление аккаунта (создаёт папку в `inbox` и свои настройки), подключение и переподключение к TikTok, отключение, ссылка в профиль (хранится для копирования, отметка «уже указана в TikTok»).

Данные панели лежат в `infra/files/accounts/<аккаунт>.json` (ссылка, дата добавления) и `infra/files/pools/<аккаунт>/` (свои списки текстов).

## Панель для сотен и тысяч аккаунтов
- **Вкладка Accounts:** таблица с поиском (клавиша `/`), быстрыми фильтрами (требуют внимания, не подключены, мало видео, без видео, активные, простаивают, с ошибками), группами, сортировкой по колонкам и пагинацией (25-200 строк). Сверху плитки со сводкой по всем аккаунтам. Клик по строке раскрывает подробности: шаги онбординга, ссылку в профиль, группу, кнопки подключения, отключения и перехода к текстам аккаунта.
- **Массовые действия:** отметьте строки (или «Select all N matching») и назначьте группу или скопируйте списки хуков, подписей и хэштегов с одного аккаунта на выбранные.
- **Add accounts:** вставьте до 1000 имён сразу (через строку, пробел или запятую), можно сразу указать группу. Создаются папки в `inbox` и настройки.
- **Texts и Videos:** выбор аккаунта через поле с подсказками (имена подгружаются по мере ввода), поиск и постраничная выдача.
- Данные: настройки аккаунтов `infra/files/accounts.json`, кэш статистики `infra/files/panel_cache.json` (можно удалять, пересоберётся).

## Расписание (вкладка Schedule)
По умолчанию планировщик **на паузе**: сам ничего не планирует и не публикует. Кнопка «Resume scheduler» включает его; «Pause scheduler» останавливает. Ручная кнопка «Publish videos» работает независимо от расписания.
- **Профили:** сколько постов в день, окна времени (`09:00-13:00, 16:00-22:30`), минимальный интервал, дни недели, часовой пояс, «разгон» нового аккаунта. Профиль назначается группе; у одного аккаунта можно переопределить профиль и число постов (подробности строки на вкладке Accounts).
- **Как работает:** раз в минуту планировщик строит слоты на сегодня и завтра (случайное время в окнах), заранее готовит ролики (хук, подпись, музыка), а в момент слота публикует. Слоты, опоздавшие больше N часов (по умолчанию 6), пропускаются.
- **Паузы:** общая, по аккаунту, автоматическая (проблемы со входом или ограничениями приложения, лимиты TikTok на несколько часов, несколько ошибок подряд). Список приостановленных виден во вкладке Schedule, там же кнопка «Resume».
- **Лента:** будущие слоты с кнопкой «Skip» и последние результаты. «Publish now» (у аккаунта или массово) ставит ручной слот, который выполняется даже при паузе планировщика.
- Работает, только пока включены ПК, Docker Desktop и ngrok. Отключите спящий режим Windows.
- Файлы: настройки `infra/files/schedule.json`, слоты `infra/files/plan/`, подготовленные ролики `infra/files/prepared/`, сводка `infra/files/plan_summary.json`, паузы `infra/files/state/paused/`.

## Приглашения для владельцев аккаунтов (вкладка Invitations)
Владелец подключает свой TikTok-аккаунт сам, по личной одноразовой ссылке, не получая ваш ключ доступа.
1. **Создание:** вкладка Add accounts, блок «Invite account owners» (имена по одному в строке, заметка «кто пригласил», срок 3-30 дней), либо кнопка «Invite owners» у выбранных аккаунтов, либо «Invite owner» в подробностях аккаунта. Новые имена добавляются автоматически.
2. **Рассылка:** вкладка Invitations показывает новую пачку ссылок: «Copy all», «Copy ready-to-send messages» (готовые тексты для отправки владельцам) и «Download CSV».
3. **Владелец:** открывает ссылку, видит страницу «Connect your TikTok account» (что запрашивается и как отозвать доступ), нажимает «Continue to TikTok», входит и разрешает доступ, видит «Thank you». Ссылка срабатывает один раз; новая ссылка для того же аккаунта отзывает прежнюю.
4. **Отслеживание:** статусы Pending (создано), Opened (открыл ссылку, есть дата и число открытий), Connected (подключился), Expired, Revoked. Статус виден в таблице приглашений, в подробностях аккаунта (шаг «Invited» в онбординге) и в фильтре «Invited» на вкладке Accounts. Неудачная попытка (отказ в TikTok, сбой обмена кода) приглашение не расходует.
5. **Безопасность:** `state` при подключении из панели теперь подписан (HMAC на основе `CONNECT_SECRET`), поэтому подключить токены под чужим именем аккаунта подделкой запроса нельзя. Приглашения лежат в `infra/files/invites/`.
Ссылка работает, пока включены ПК, Docker Desktop и ngrok, а в приложении TikTok указан подходящий Redirect URI.
